## 一、项目概述

PlantsDB（植物标准基因组库）是一个生物信息学流程项目，旨在构建标准化的植物基因组资源。项目覆盖从物种列表管理、NCBI基因组批量下载、数据标准化处理、蛋白质性质计算到同源基因鉴定的完整工作流，并在此基础上构建 Agent 智能查询助手和 API 接口层，为合作公司搭建的前端网页提供数据服务。

**当前规模**：去重后约 2010 个物种

**团队分工**：
- 本团队（nizhu 等 ~7人）：数据管线、Agent 框架、API 接口层
- 合作公司：数据库存储搭建、前端网页开发

### 阶段五：API 接口层开发（5月中旬–6月中旬）

> 此阶段与数据管线并行推进，不依赖全量数据完成

#### 5.1 数据模型设计
- 定义核心数据实体：Species、Genome、Protein、HomologPair、SyntenyBlock
- 设计数据关系：物种→基因组→蛋白质、物种对→同源关系
- **输出**：数据模型文档（ER 图、字段定义），交付合作公司作为数据库建表依据
- 时间：5月中旬

#### 5.2 REST API 开发
- 基于 Flask/FastAPI 构建 API 服务
- 核心 API 端点设计：
  - `GET /api/species` — 物种列表（分页、按目/科/属筛选）
  - `GET /api/species/{id}` — 物种详情（基因组信息、文件列表）
  - `GET /api/species/{id}/proteins` — 物种蛋白质列表
  - `GET /api/proteins/{id}` — 蛋白质详情（pI、MW、长度、序列）
  - `GET /api/homologs` — 同源基因对查询（按物种对/属筛选）
  - `GET /api/homologs/{id}` — 同源基因对详情
  - `GET /api/stats` — 统计数据（目/科/属物种数、下载状态）
  - `GET /api/search` — 全局搜索（物种名、基因名、登录号）
- **输出**：OpenAPI/Swagger 规范文档 + 可运行的 API 服务
- 时间：5月下旬–6月上旬

### 阶段六：Agent 智能查询助手框架（5月下旬–7月上旬）

> 这是项目新增的核心模块，需要从零设计

#### 6.1 架构设计（5月下旬–6月上旬）

**设计目标**：用户用自然语言查询基因/物种/同源关系，Agent 自动理解意图并调用工具查询

**核心架构**：
```
用户输入（自然语言）
    ↓
意图识别 & 实体抽取（LLM）
    ↓
工具调度（Tool Router）
    ├── 查询物种信息 → 调用 /api/species
    ├── 查询蛋白质性质 → 调用 /api/proteins
    ├── 查询同源关系 → 调用 /api/homologs
    ├── 查询分类统计 → 调用 /api/stats
    ├── 全局搜索 → 调用 /api/search
    └── 序列检索 → 调用序列查询工具
    ↓
结果整合 & 自然语言回复（LLM）
```

**技术选型**（待定）：
- LLM 后端：OpenAI API / 开源模型（如 Qwen、ChatGLM）
- Agent 框架：LangChain / LlamaIndex / 自研轻量框架
- 工具注册：Function Calling / ReAct 模式

**输出**：架构设计文档（组件图、数据流、接口定义、LLM 选型方案）

#### 6.2 工具层开发（6月上旬–6月中旬）

- 将阶段五的 REST API 封装为 Agent 可调用的工具（Tool）
- 每个工具定义：名称、描述、参数 schema、调用逻辑
- 实现工具：
  - `search_species` — 按名称/分类搜索物种
  - `get_species_detail` — 获取物种基因组详情
  - `get_protein_properties` — 查询蛋白质理化性质
  - `find_homologs` — 查找同源基因
  - `get_statistics` — 获取分类统计数据
  - `search_sequence` — 序列检索（BLAST/关键词）
- 添加结果格式化，使 LLM 能理解返回的结构化数据

#### 6.3 对话引擎开发（6月中旬–6月下旬）

- 实现对话状态管理（多轮对话、上下文保持）
- 意图识别与工具路由
- 结果整合与自然语言生成
- 对话历史记录与回溯
- 异常处理（无结果、模糊查询、多义意图）

#### 6.4 前端集成与测试（6月下旬–7月上旬）

- 与合作公司对接，将 Agent 嵌入前端聊天组件
- API 端点：`POST /api/chat`（接收消息，返回流式/非流式回复）
- 端到端测试与 prompt 调优
- 边界场景处理：未知物种、跨物种查询、批量查询

> **里程碑 M6**（7月5日）：Agent 框架上线，可完成自然语言查询物种/蛋白质/同源关系

## 五、风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|----------|
| NCBI 下载速率限制或服务中断 | 延迟数据获取 | 利用断点续传，分时段下载，准备备选镜像 |
| 磁盘空间不足（预估 2-10 TB） | 无法存储全量数据 | 提前规划存储，优先下载核心物种 |
| GeneTribe 大属计算时间过长 | 延迟阶段四 | 增加并行度，优先处理小属，大属可拆分 |
| 部分物种无组装数据 | 数据不完整 | 记录缺失物种，标记为"待补充" |
| 合作公司前端进度不确定 | 影响联调与上线 | 提前交付 API 文档，独立开发测试 |
| LLM API 成本/延迟 | Agent 体验不佳 | 优先使用开源模型部署，缓存高频查询结果 |
| Agent 意图识别准确率 | 用户查询结果不对 | 充分的 prompt 工程 + Few-shot 示例，逐步优化 |
